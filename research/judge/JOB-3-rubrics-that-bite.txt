SECTION 1. What counts as checkable: the two-expert agreement test

Checkable means graders agree. The claude-api skill audit file says: "Unambiguous success criteria. Would two independent domain experts, shown the same output, agree on pass vs fail? If the criteria admit reasonable disagreement ('write a *good* summary'), scores reflect grader opinion as much as model capability."
The build file says to write rubrics "as concrete, checkable claims ('the response cites at least one source from the context'; 'the response does not fabricate API parameters') rather than vague scales ('rate helpfulness 1-5')."
The Anthropic docs give the bad/good pair: Bad "The model should classify sentiments well"; Good "an F1 score of at least 0.85 ... on a held-out test set of 10,000 diverse Twitter posts". And Bad "Safe outputs" vs Good "Less than 0.1% of outputs out of 10,000 trials flagged for toxicity by the content filter."
Gap: the fetched doc extract has no step for testing whether a criterion ever returns FAIL. It lists "Likert scales: 'Rate coherence from 1 (nonsensical) to 5 (perfectly logical)'" as acceptable; the skill file calls that style "vague scales".
Mechanic: have two graders label 20 real outputs per criterion; where they disagree on more than a couple, the criterion is decorative until rewritten as an observable property.

SOURCE: repo: claude-api skill, files shared/evals/eval-audit.md (section 2/"Task design") and shared/evals/build-eval.md (Step 2 grading method 3); doc: https://platform.claude.com/docs/en/test-and-evaluate/develop-tests
COSTS: one model, 20 sample outputs per criterion, no training. Doc quotes came via a summarizing fetch.

SECTION 2. Known-bad inputs: oracle, null, empty, wrong-answer (the minimum check your four checkers skipped)

The claude-api skill states the exact test for "a judge that cannot fail": "Before the first full pass, run (a) an oracle ... and (b) a null baseline - empty output, a constant answer, or the majority class - through the whole pipeline. If the oracle doesn't pass, the harness or grader is broken; if the null doesn't fail, the grader is too lenient."
For judges specifically: "Tested on known negatives. Feed the judge an empty string, 'I don't know', and a confident answer to the wrong question; confirm it fails all three." And: "Well below ~90% [human agreement] on clear-cut cases means the judge prompt needs another iteration."
Also: "A rubric that looks sensible in the abstract can turn out to reward the wrong thing; the only way to catch that is to look at what it actually does."
Why the null test matters: Zheng et al. 2024 show that "even a 'null model' that always outputs a constant response (irrelevant to input instructions) can cheat automatic benchmarks and achieve top-ranked win rates: an 86.5% LC win rate on AlpacaEval 2.0; an 83.0 score on Arena-Hard-Auto; and a 9.55 score on MT-Bench." Those are published benchmarks with rubric-style judge prompts, passed by an output that ignores the question.
Mechanic: keep a folder of 5 to 10 fixed known-bad files per craft (empty, off-topic, plausible-but-wrong, and your already-known broken file). Every checker run must include them and the run is invalid unless they fail.

SOURCE: repo: claude-api skill, shared/evals/eval-audit.md (sections 2 and 3, "When the grader is an LLM judge") and build-eval.md (Step 3 oracle/null paragraph); Zheng, Pang, Du, Liu, Jiang, Lin 2024, "Cheating Automatic LLM Benchmarks: Null Models Achieve High Win Rates", https://arxiv.org/abs/2410.07137
COSTS: a handful of hand-made bad files; one extra judge call per bad file per run.

SECTION 3. Seeded-defect testing: measure the detection rate of your own checker

Doddapaneni, Khan, Verma, Khapra 2024 (FBI) take good answers, inject a defect that clearly hurts one quality, and test whether the evaluator notices. "By introducing targeted perturbations in answers generated by LLMs, that clearly impact one of these key capabilities, we test whether an Evaluator LLM can detect these quality drops. By creating a total of 2400 perturbed answers covering 22 perturbation categories ... Evaluator LLMs ... failed to identify quality drops in over 50% of cases on average."
Body text: "even basic perturbation categories, such as, fluency perturbations (e.g. spellings and grammar) posed challenges for the evaluators. We also observed cases where Evaluator LLMs did not adjust their scores for perturbed responses despite correctly identifying the perturbations in their explanations." They also tried "providing a rubric, asking for a justification, specifying the axis of evaluation" and still found evaluators "consistently performed poorly"; "reference-based evaluations showed comparatively better performance."
Judge Reliability Harness (Dev et al. 2026) packages the same idea: tests built from "simple text formatting changes, paraphrasing, changes in verbosity, and flipping the ground truth label"; "No judge that we evaluated is uniformly reliable."
Mechanic: for each criterion in your standard, write a script or prompt that damages a passing file in exactly that way (delete the required section, flip a number, break the format). Detection rate per criterion = fraction of damaged files the checker flags. A criterion below roughly 80% detection is decorative. Also read the checker's explanation: if it names the defect but still passes, the verdict field is disconnected from the reasoning.

SOURCE: https://arxiv.org/abs/2406.13439 (FBI; code github.com/AI4Bharat/FBI); https://arxiv.org/abs/2603.05399 (Judge Reliability Harness; github.com/RANDCorporation/judge-reliability-harness)
COSTS: one model; roughly 5 to 20 damaged variants per criterion, produced by script or by the model. The 80% threshold is my suggestion, not from the papers.

SECTION 4. Per-criterion discrimination: does each criterion separate good from bad?

Arabzadeh et al. 2024 (AgentEval) add a VerifierAgent that tests each generated criterion. "Discriminative Power: A reliable evaluation should detect and withstand noise. To test that, we propose to use adversarial examples and then assess the system's ability to differentiate between these compromised examples and standard cases. Should the system fail to distinguish effectively, it indicates that the criteria are insufficient for reliable assessment."
They also test stability: 50 repeated runs on 120 problems, plotting quantifier scores for successful vs failed cases. "The more robust a criterion, the narrower the range of quantified performance ... the less overlap between the successful and failed boxes, the higher the distinguishability of the criteria." Result: "all four criteria, except 'error analysis' allow for easy differentiation between successful and failed cases." One of four criteria in a published rubric did not separate success from failure.
A second case of per-criterion blindness: Autorubric (Rao and Callison-Burch 2026) reports on CHARM-100 "0.70 recall for brevity but 0.14 for verbosity, a distinction invisible in holistic scores." A single overall pass rate hides that the judge catches one defect and misses the other.
Mechanic: label 20 files good and 20 known-bad for the craft. Run each criterion alone. Report per criterion: pass rate on good, pass rate on bad, and repeat-run variance. A criterion whose pass rate on bad files equals its pass rate on good files carries no information and should be cut or rewritten.

SOURCE: https://arxiv.org/abs/2405.02178 (AgentEval, sections 6.2, 6.2.1); https://arxiv.org/abs/2603.00077 (Autorubric, discussion section)
COSTS: 40 labeled files per craft, one judge call per file per criterion, repeated 3 to 5 times. No GPU.

SECTION 5. Documented rubric that looked rigorous and failed: agreement is not validity (PReMISE)

Roy et al. 2026 audit rubric sets on four axes and report: "Across rubric sources no raw source is simultaneously reliable, preference-predictive, and adversarially robust; and high inter-rater agreement does not imply low exploitability." In the body: "agreement is not validity ... judges can agree on a flawed interpretation, and a rubric that predicts preferences on ordinary responses can still admit adversarial responses that exploit its wording."
The test is the Verified Fool Rate: "an attacker generates a candidate response designed to score highly under c while violating its intent. The judge scores the candidate. A separate verifier, blind to both the attack strategy and the judge score, labels high-scoring candidates as genuine or exploiting." Their repair, reliability-constrained refinement, "reduces the rate at which exploit responses receive high scores from 46.4% to 36.0% with little change in inter-judge agreement (alpha = .531 to .519)". So before repair nearly half of attacker responses fooled the rubric, while inter-judge agreement looked acceptable at .53, and agreement barely moved when exploitability dropped by 10 points. Agreement statistics cannot tell you the rubric is fooled.
Mechanic: for each criterion, task a second model with "write an output that passes this criterion's text while violating what it is for." Count how many pass. Check by a different model or a human.
Caveat: the verifier is a model; the paper validates it on only 42 samples against 3 human annotators (Appendix B.5).

SOURCE: Roy, Pujari, Kumarage, Peris, Gupta, Rumshisky 2026, "PReMISE: Policy Rubrics as Measurement Specifications for LLM Judges", https://arxiv.org/abs/2605.30803
COSTS: an attacker model plus a verifier model call per criterion; tens of attempts per criterion.

SECTION 6. Specific is not the same as safe: tailored criteria were exploited more than a generic one (ImpossibleRubrics)

Qin et al. 2026 generate rubrics for tasks where the only honest answer is "this cannot be done," and test whether the rubric rewards fabricated answers. "Eleven generators are exploited 8-26% of the time on the unbiased 150-of-169 environment cut; on a deliberately selected stress cut the strongest generator we measured is still exploited 36% while a certificate-faithful rubric is exploited 0%."
The surprising result: "A single generic rubric ('be decisive, penalize hedging') used unchanged for every task is exploited 64% of the time, and seven of the eleven generators are exploited more often than that while writing a rubric tailored to each one. The tailored criteria appear to tell an attacker which claim to fabricate. The problem is not that rubrics are vague; it is that they are specific about the wrong things."
Reading for your situation: a standard can be detailed, concrete and measurable and still have no way to say "this task has no valid answer" or "the output's claim is false." The oracle there is a "verifiable oracle certificate specifying what an honest answer may and may not claim", not a rubric. What bit was a written list of what is true or forbidden, checked against the output.
Caveat: the paper's tasks are a narrow construct (impossible tasks), and "appear to" is the authors' hedged wording for the causal story.

SOURCE: Qin, Xie, Liu, Yang 2026, "ImpossibleRubrics: Stress-Testing Generated Rubrics as Reward Signals", https://arxiv.org/abs/2609.16816
COSTS: for your use, a short per-task list of "must not claim / must acknowledge" facts, written by a human or model with source access.

SECTION 7. Consistency masquerading as validity: four documented cases

(a) Stability Trap (Shergadwala 2026): "judges achieved near-perfect verdict agreement (>99%) for both objective and subjective evaluations, their accompanying justification traces diverged significantly. Objective instructions requiring quantitative analysis, such as word counting, exhibited reasoning stability as low as ~19%." Conclusion: "delegate all deterministically verifiable logic to code, while reserving LLM judges for complex semantic evaluation." A checker that returns the same verdict each time may be reading the wrong thing.
(b) Rubric-only prediction (Bagaria et al. 2026): "Classifiers trained only on rubric text, without access to any evaluated response, achieve nontrivial predictive performance on judge outputs ... judges often fail to reliably update their decisions when either the candidate response or the rubric criterion is reversed."
(c) Factor collapse (Feuer et al. 2025, Arena-Hard Auto): "factor correlations above 0.93 for most criteria" and "unexplained variance exceeding 90 percent" for one judge, meaning the judge's overall verdict was not explained by its own listed criteria. Separate criteria were scored as one blur.
(d) Autorubric: LLaMA-3.1-8B in the Default configuration on CHARM-100 scored exact accuracy 19.4% with kappa -0.001, i.e. no better than chance, yet produced well-formed output.
Mechanics: re-run with the criterion text reversed (a criterion that says the opposite should flip verdicts); check pairwise correlation among criterion scores (above 0.9 means they are one criterion); and move every count, regex, schema and diff check out of the model.

SOURCE: https://arxiv.org/abs/2601.11783 (Stability Trap); https://arxiv.org/abs/2609.02942 (Bagaria et al.); https://arxiv.org/abs/2509.20293 (Feuer et al.); https://arxiv.org/abs/2603.00077 (Autorubric, section 4.4 table)
COSTS: re-runs of existing judge calls; correlation computed in a few lines of Python.

SECTION 8. Decomposition into yes/no questions: what it buys and its measured size

TICK (Cook et al. 2024): "LLMs can reliably produce high-quality, tailored evaluation checklists that decompose the instruction into a series of YES/NO questions. Each question asks whether a candidate response meets a specific requirement." Results against human preferences (exact agreement, GPT-4o judge, Table 4): direct preference 0.293; direct 1-5 scoring 0.464; check-then-score 0.487; full TICK 0.522 ("46.4% to 52.2%"). Humans scoring with checklists: Krippendorff alpha 0.194 to 0.256. The authors' own caveat: "agreement is still low." A second caveat from their human study: "a number of edge cases arise that can lead evaluators to answer most checklist questions with YES and still justifiably provide a low overall score." A checklist that is all YES does not prove quality.
FActScore (Min et al. 2023) is the atomic form: "breaks a generation into a series of atomic facts and computes the percentage of atomic facts supported by a reliable knowledge source", motivated by "binary judgments of quality inadequate"; the automatic estimator has "less than a 2% error rate" against human scores (aggregate level, with retrieval).
LLM-Rubric (Hashemi et al. ACL 2024): per-question LLM answers "often fail to agree well with human judges"; a small calibration network over 9 questions predicts overall satisfaction "with RMS error < 0.5, a 2x improvement over the uncalibrated baseline." That needs human labels and training a tiny network.
Check-Eval (Pereira et al. 2024): claims higher correlation than G-Eval and GPTScore on SummEval and a Portuguese legal similarity set; I read only the abstract.

SOURCE: https://arxiv.org/abs/2410.03608 ; https://arxiv.org/abs/2305.14251 ; https://arxiv.org/abs/2501.00274 ; https://arxiv.org/abs/2407.14467
COSTS: TICK and FActScore variants run with a prompt and a loop. LLM-Rubric needs human annotations on a few hundred outputs. FActScore needs a trusted source to check facts against.

SECTION 9. Binary vs numeric scale vs ranking: what the evidence supports and where it is thin

Binary checklist beat 1-5 direct scoring on exact human agreement: 52.2% vs 46.4% (TICK, one benchmark, one judge).
Scale width matters and is not monotone. Li et al. 2026 compared 0-5, 0-10, 0-100: "the 0-5 scale shows the strongest pooled human-LLM alignment, while the 0-10 scale yields the weakest" and "the choice of scale substantially shifts human-LLM agreement, even when within-group panel reliability is high." On subjective tasks LLM panel ICC on the 0-5 scale was 0.632 (MT-Bench) and 0.573 (SummEval), against 0.899 and 0.930 for humans.
Contrary evidence for fine scales in retrieval: Godfrey et al. 2025: "the gap between pointwise scoring and listwise ranking shrinks when pointwise scoring is implemented using a sufficiently large ordinal relevance label space." That is relevance judging, not craft quality.
Pairwise: Tripathi et al. 2025: "pairwise protocols are more vulnerable to distracted evaluation ... Pairwise preferences flip in about 35% of the cases, compared to only 9% for absolute scores." The claude-api skill's statement that pairwise "tends to be more accurate" than pointwise carries no citation, and this paper cuts against it for manipulable features.
Match format to construct. Autorubric: ordinal criteria "show lower exact accuracy (38-58%) but high adjacent accuracy (85-93%)"; "match criterion format to the construct - binary for defensible thresholds and ordinal for meaningful gradations ... rather than treating one format as universally preferable." Prometheus's training text warns against "giving a score of 1 for all responses that lack a minor detail or giving a score of 5 for all responses that seem to be good on the surface."

SOURCE: https://arxiv.org/abs/2601.03444 ; https://arxiv.org/abs/2505.19334 ; https://arxiv.org/abs/2504.14716 ; https://arxiv.org/abs/2603.00077 ; https://arxiv.org/abs/2310.08491 ; repo: claude-api skill build-eval.md
COSTS: re-scoring a set of 30 to 50 files under each format; compare to human labels.

SECTION 10. Anchoring with examples and reference answers: measured effects are modest or caveated

MT-Bench (Zheng et al. 2023): three worked judgments (A better, B better, tie) "can significantly increase the consistency of GPT-4 from 65.0% to 77.5%. However, high consistency may not imply high accuracy and we are not sure whether the few-shot examples will introduce new biases. Besides, the longer prompts make API calls 4x more expensive." Reference answers matter more: judge failure on 10 math questions was 14/20 with default prompt, 6/20 with chain of thought, 3/20 with a reference answer ("a failure means when GPT-4 says an incorrect answer is correct").
Prometheus (Kim et al. 2023): ablation of a trained 7B judge, Pearson with GPT-4 labels: full 0.860; "w/o Score Rubric" 0.837; "w/o Reference Answer" 0.642. "excluding the reference answer shows the most significant amount of performance degradation." Caveats: the target scores are GPT-4's, not humans'; it applies to a fine-tuned model.
Autorubric: 5-shot calibration raised accuracy 78.0% to 80.7% (+2.7 points); "54 decisions improve and 32 degrade"; authors call it descriptive.
Huynh et al. 2026: "rubric edits providing representative examples along with contextual information increased human-autorater agreement as well as autorater self-agreement."
Net: a reference answer or known-correct artifact helps a lot; score-level example anchors help a little and can hurt individual cases. G-Eval gave no few-shot ablation (see NOT FOUND).

SOURCE: https://arxiv.org/abs/2306.05685 ; https://arxiv.org/abs/2310.08491 ; https://arxiv.org/abs/2603.00077 ; https://arxiv.org/abs/2605.06283
COSTS: a gold reference per task (human-made); few-shot examples add prompt length (MT-Bench measured 4x cost).

SECTION 11. 3 vs 10 vs 30 criteria: indirect evidence only

No controlled study was found that varies criterion count while judging each criterion separately (NOT FOUND). Indirect findings:
Rubrics judged together in one call interfere. Yu et al. 2026: "the verdict on one rubric shifts depending on which other rubrics are co-present. In a preliminary study, only one-third of samples receive fully consistent verdicts when evaluated under rubric sets of varying composition." On ResearchQA, as co-evaluated rubrics grew from 2 to 8, deviation from the isolated verdict "Qwen3-32B climbs from .203 at K=2 to .362 at K=8, nearly doubling." HealthBench rubrics per sample range 2 to 32. Even FLASK with 3 criteria: "even minimal rubric sets trigger measurable interference."
Peng et al. 2026 (RuVerBench): in agentic coding, "once a call contains four or five rubrics, every tested model loses score, often by double digits."
Huynh et al. 2026: "higher criterion complexity ... tended to decrease human-autorater agreement."
Feuer et al. 2025: criteria collapse into one factor (section 7), so more criteria do not mean more independent measurements.
Autorubric's pattern (one call per criterion, N x M calls) avoids the interference. Mechanic: one criterion per call; delete any criterion whose scores correlate above about 0.9 with another.

SOURCE: https://arxiv.org/abs/2608.14684 ; https://arxiv.org/abs/2606.29920 ; https://arxiv.org/abs/2605.06283 ; https://arxiv.org/abs/2509.20293
COSTS: N criteria means N calls per file; cost scales linearly, no training. Models in these studies were mostly open-weight 8B to 32B; frontier-model effect size unknown.

SECTION 12. Assembled protocol for one standard (built only from sections above)

1) Write each criterion as an observable property and confirm two graders agree on 20 real outputs (section 1).
2) Move every deterministic property (counts, schema, file exists, diff scope) into code (section 7a; claude-api skill "grade the end state, not the transcript").
3) One criterion per judge call, binary unless the construct has real gradations (sections 9, 11).
4) Attach a human-written reference artifact that passes (section 10).
5) Run the known-bad folder; run is void if any known-bad passes (section 2).
6) Seed one defect per criterion; require detection (section 3).
7) Report pass rate on good vs bad for each criterion; delete criteria that do not separate them (section 4).
8) Ask a second model to write an output that passes the text while violating the intent; count successes (section 5).
9) Add a written list of facts the output must not claim, checked against the output (section 6).
10) Re-run a reversed criterion; verdicts must flip (section 7b).
All of this is derived from the cited work; the combination has not been tested as a whole in any source found.

SOURCE: sections 1 to 11 above; repo: claude-api skill eval-audit.md
COSTS: one model, one machine; the main cost is the 40 labeled good/bad files per craft.
